# M1 by hand

A short pass over what M1 ships, in a browser. Everything here is also covered by e2e (`e2e/tests/`), the drills
and the parity gate; this is for eyes on it before the release options.

## Run it (PowerShell, from the repo root)

```powershell
app\run.bat                                                # skeleton: http://127.0.0.1:8080, data in app\data.db (seeded)
$env:PROFILE='minimal'; app\run.bat 8081; $env:PROFILE=''  # minimal: http://127.0.0.1:8081, notes in memory
```

`app\prepare.bat` runs first only on a fresh clone. Use `127.0.0.1`, not `localhost` (the server listens on IPv4
only, and `localhost` tries `::1` first). Ctrl+C stops it, within about 6 s. `$env:OPEN='1'` opens the browser
too. `app\bin\skeleton.exe --features --json`, `--routes --json` and `--limits` print what the build mounts.

## skeleton (http://127.0.0.1:8080)

| Where | Try | Expect |
|---|---|---|
| `/` Dashboard | load it; click a stat card and a tile | numbers count up, sparklines; a card drills through to `/data` filtered |
| `/components` | the showroom, tabs, accordion, modal, drawer, toasts | all animate; clicking outside the modal does **not** close it, outside the drawer does |
| `/forms` | a bad email (blur), the slider, submit empty, then submit valid | inline error on blur; 422 keeps what you typed; success adds a contact, toasts, resets the form |
| `/data` | filter, status chips, sort, pager; add a row (try a bad email); cycle a status; delete | error lands in the form's slot; new row animates in; counts follow |
| a row's drawer | open; timeline and related; Edit with a bad value, then a good one; Delete | 422 re-renders the form as typed; the table row refreshes behind the drawer |
| top-bar search | type `a`, then Enter; Escape | highlighted matches; Enter goes to `/data?q=a`; Escape or a click outside closes it |
| theme picker | change style and scheme; reload | sticks, no flash; 6 styles × 23 schemes |
| nav links | move between pages; browser back | body swaps without a reload, the title follows |
| `/nope` | | the 404 page inside the layout |
| `/healthz`, `/livez`, `/readyz?detail` | | `ok`, `ok`, `ready store ok` |
| `/licenses`, `/robots.txt`, `/sitemap.xml` | | the notices; the same Disallows as 1.2.x; the nav pages |

Restart `run.bat`: your edits are still there (`app\data.db`). A 1.2.x `data.db` copied in opens in place, adopted by
the contacts store.

## minimal (http://127.0.0.1:8081)

Home: add a note (newest first); an empty one shows its error in the form; About. Restart: the notes are gone (the
memory store, by design). The theme is the lite one: `modern` with `midnight` and `daylight`.

## Different from 1.2.x on purpose

- Every response carries `x-request-id` and `x-version`; skeleton also sends Permissions-Policy, COOP and CORP (X35).
  `minimal` keeps 1.2.x's exact header set.
- The console's access log is logfmt, one line per request (id, route, status, µs, a hashed client id; never the
  query). `LOG_LEVEL=warn` silences it.
- New endpoints: `/livez`, `/readyz` (`?detail`), `/licenses`, and `/metrics` (404 without its bearer token,
  `METRICS_TOKEN_FILE`).
- A write waits for its batch on the writer task; a full queue answers 503 with `retry-after`.
- A crash in a handler answers 500 and serving goes on; one that touched shared state drains and exits 70.
- Chunked request bodies: framing past the body cap answers 413, a bare LF in it 400.

## Look closely at

- **The writes on `/data` and in the drawer** (add, edit, cycle, delete): they go through the writer task and come
  back as deferred responses now. Watch the row refresh and the toast, and click fast: nothing lost or doubled.
- **Errors that keep your input**: `/forms`, the inline add, the drawer edit.
- **The console while you click**: one readable access line per request, nothing at warn or error.
- **Stopping**: Ctrl+C ends it cleanly within a few seconds, mid-click too.
