# S0.9 Linux leg on the dev PC

**Closes:** 12 and 13 measured mostly on Windows · **Pass criterion:** Odin dev-2026-10 installed in WSL2 (Q5: yes), with 03
§10.3's obj + lld recipe as the fallback; a TSan build runs
**Result:** PASS: Odin dev-2026-10 runs natively in WSL2, the skeleton builds and passes its tests there, and TSan builds
run and report; the obj + lld fallback isn't needed · **Date:** 2026-10-26 · **Commit:** ddfff0f

## Decision

The Linux leg runs on native Odin in WSL2 from now on (§18.5's "Linux leg" row): builds, the parity gate's second leg,
TSan and ASan. 03 §10.3's recipe (objects from Windows, linked in WSL with lld) is retired; nothing needs it.

One finding changes how the TSan gates read: a TSan build of the stream prototype reports data races inside Odin's own
`core:nbio` (its cross-thread queue, `mpsc_enqueue`, `core/nbio/mpsc.odin:36`), not in the fork or the app. The line is
a debug `assert` that reads a queue slot without an atomic load while the consumer exchanges it atomically: a formal
data race, harmless on x86-64. M2's "TSan 0 reports on hub, stream, workers" gate therefore needs a suppression for that
one frame (`race:nbio::mpsc_enqueue` in a `tsan.supp` the gate passes through `TSAN_OPTIONS`), removed when an Odin bump
fixes the read. Folded into the M2 gate (PLAN §22.3, D44), R3 (both) and §18.5's Linux-leg row; see Caveats.

## Method

- **Install** (one-time dev tooling, Q5): the official `odin-linux-amd64-dev-2026-10.tar.gz`, checked against the SHA-256
  that the skeleton's CI and Dockerfile pin (`c3c8b095…a8ab`), unpacked to `/opt/odin` and linked onto `PATH`; clang,
  lld and llvm from the distro (clang 18.1.3), plus `unzip` for `prepare.sh`. WSL2's distro is Ubuntu, kernel 6.18
  (Microsoft's WSL kernel), 16 threads and 31 GiB visible.
- `odin version` reports `dev-2026-10-nightly:84bc3fc`, the same commit as the Windows install; `odin report` shows the
  LLVM 20.1.8 backend.
- **Builds** run from a copy in WSL's own filesystem (`git archive HEAD app`), not from the Windows mount.
- **TSan:** a two-thread counter with no lock (`-sanitize:thread -debug`), then the stream prototype on the fork (03's
  server, `-sanitize:thread -debug`) driven by 03's 29 contract checks from the Windows side.
- **ASan:** the same two-thread program built with `-sanitize:address -debug`.

## Caveats

- WSL2 shares the dev PC's CPU with Windows, so the Linux leg carries the same background noise as the Windows leg
  (§18.5, R13); the parity gate's paired rounds are what make it usable.
- The `core:nbio` race is read from the source (`mpsc.odin:36`, a plain read inside `assert`); whether Odin's master has
  changed that line since dev-2026-10 is UNVERIFIED (the next Odin bump, R3).
- A TSan build did not shut down on SIGINT: the stream prototype installs no handler, and TSan defers the default
  action while every thread waits in `io_uring_enter`. Gates that need a clean exit under TSan send the drain through
  the app (the M2 drill), or SIGKILL after reading the report.
