# S0.10 Bundles

**Closes:** S13's mechanics; the Windows brotli gap · **Pass criterion:** `tools/bundle` builds the four bundles + br/gz from the `EXTS` scan; `bundle-race.spec` 9/9 per engine with assets delayed 400 ms; the minimal bundle's SHA equals the skeleton's `htmx.min.js`
**Result:** PASS with a change — all three parts pass in Chromium and WebKit on Windows, and the plan needs four small additions (Decision) · **Date:** 2026-10-26 · **Commit:** ddfff0f

## Decision

`tools/bundle/main.odin` is the M1 base for the tool. M1 moves the fixture's `platform/ext` to `app/platform/ext` and
points the tool's import at it. The plan keeps D19 as written, plus four additions. PLAN.md and DECISIONS.md are
unchanged; the edits are proposed in the spike report.

1. **How a build asks for a fixed page bundle.** `scripting_web` and `compat_web` each declare one line,
   `BUNDLES :: bit_set[web.Bundle]{.Scripting}` (and `{.Compat_Htmx2, .Compat_Alpine}`). The tool builds Main plus
   every bundle a reached package names. `web.Bundle` and its fixed table (`PAGE_EXTS`) live in `platform/ext` beside
   `Ext`, so the tool imports them. `tools/check exts` covers `BUNDLES` lines too.
2. **The scan is a build, and the app tolerates a missing bundle at compile time.** Odin's `-export-dependencies`
   works with `build`, `run` and `test`, not `check`. A failed `#load` aborts the build before the list is written. So
   the app `#load`s each bundle file under `when #exists(...)`, and boot check 6 refuses a binary built before prepare
   ("run prepare"). A link failure doesn't matter: the list is written before linking.
3. **Compression.** The tool runs `brotli -q 11 -f` and `gzip -9 -n -k -f`, which write beside the input (never
   through a pipe). On Linux both are required; a missing one is fatal. On Windows the tool looks on the PATH, then in
   Git for Windows (`git --exec-path`), which ships both. A Windows build without one ships the encodings it has, and
   stale `.br`/`.gz` files are deleted. The Windows brotli gap is closed: the outputs are byte-identical on both OSes.
4. **Names and header.** The header is `/* exts: <names in load order> */` and a newline. An empty union gets no
   header, so `minimal`'s bundle is `htmx.min.js` exactly; boot reads a headerless bundle as the empty set. Main keeps
   htmx's name, `htmx.<crc32>.min.js`, so `minimal` serves the skeleton's URL.

## Method

**Box:** the dev PC (Windows 11), shared with other agents during the run; Ubuntu (WSL2) on the same PC for the
Linux leg. **Toolchain:** Odin dev-2026-10 (nightly 84bc3fc) on both; Node 22.16; Playwright 1.63.0 with its
Chromium 153.0.8010.12 and WebKit 26.6. Firefox does not start on this PC (R15).

**Inputs.** The htmx 4.0.0 tarball from its pinned URL
(`https://registry.npmjs.org/htmx.org/-/htmx.org-4.0.0.tgz`, SHA-256 `f252cb57…f174d`), extracted with `tar`. All 18
files used (`htmx.min.js` and 17 `dist/ext/*.min.js`) match 04 §1.3's per-file SHA-256 pins. `htmx.min.js` is
`e484d917…593f`, the skeleton's pin. `_hyperscript.min.js` 0.9.94 matches its pin `4f48d737…b86a`.

**The fixture.** There are no feature packages yet, so `tools/bundle/fixture/` holds a small tree with the plan's
shape: `build.{sh,bat}` with the four family flags per profile, `app/platform/{ext,web,html}`, the `client` and
`theme` members, three identity members, a `notes` store in both families, and feature packages with one-line `EXTS`
or `BUNDLES`. The `EXTS` lines of `video`, `wiki`, `lists` and `lab` are the fixture's choice, made so the unions
reproduce PLAN §7.1 and §12.1's lists. `orphan_web` declares `.Live` and no profile imports it.

| Profile | Families (store, identity, client, theme) | Packages with `EXTS` / `BUNDLES` | Main |
|---|---|---|---|
| `minimal` | memory, anonymous, vanilla, lite | none | htmx alone |
| `streams` | memory, nick, vanilla, lite | chat_web + 4 transports, bot_web | 10 extensions (PLAN §7.1's list) |
| `full` | sqlite, accounts, hyperscript, full | as streams, plus video, lists, wiki, lab; scripting, compat | 13 (§12.3's thirteen) + 3 page bundles |
| `lab` | memory, anonymous, hyperscript, full | wiki, lab; scripting, compat | 5 + 3 page bundles |

**Commands**, from the repo root:

```sh
odin build tools/bundle -out:<tmp>/bundle -vet -strict-style -warnings-as-errors
<tmp>/bundle <profile> --repo tools/bundle/fixture --htmx <dist> --out <tmp>/out [--list]
CMD=run OUT=<tmp>/<p> tools/bundle/fixture/build.sh <p> -define:BUNDLE_DIR=<tmp>/out -vet -strict-style   # boot check 6
```

On Windows the same with `build.bat`. On Linux, brotli came from Ubuntu's `brotli_1.1.0-2build2_amd64.deb`
(`apt-get download`, extracted, not installed); WSL's Ubuntu has none by default. The e2e spike runs from `e2e/`:

```sh
npx playwright test -c spikes/S0.10/playwright.config.ts --project=files --project=chromium --project=webkit
```

Its global setup fetches and checks the pinned files, builds the tool, bundles the four profiles and starts
`server.ts`. That server stands in for the Odin binary: it serves the bundles under crc32 names with br > gzip >
identity, `Vary` and one ETag per encoding, and answers SSE, WebSocket, multipart and an echo.

**`bundle-race.spec`.** `page.route` holds every `/static/` asset 400 ms. A file that loads after the core
(hyperscript, or an extension file in the control) waits 400 ms more, so it lands after htmx has initialised. Nine
cases per engine: three layouts × three runs. Each case checks that `hx-ws:connect`, `hx-sse:connect` and
`hx-multipart:connect` fired; that the `hx-ws:send` form echoed without navigating; with hyperscript, that
`hs-include` data arrived; that no CSP violation fired; that hx-csp stripped exactly the one unnonced element on the
nonce page; and that the bundle came as br or gzip. A control loads the same 13 extensions as separate deferred
files and is marked `test.fail()`, so it proves the delay reproduces the race.

| Layout | Page | CSP |
|---|---|---|
| Main, vanilla client | `full`'s Main bundle | the skeleton's hash CSP |
| Main + hyperscript | the same, then `_hyperscript.min.js` as its own deferred tag | the hash CSP |
| Scripting + hyperscript | `full`'s Scripting bundle (hx-csp first), then hyperscript; `safeEval` | `.Nonce_Csp` |

## Caveats

- The fixture is not the app. Its `EXTS` assignments for video, wiki, lists and lab are chosen to reproduce the
  plan's lists. The real unions of `streams` and `lab` come from M1–M2 packages: **UNVERIFIED (M2)**.
- `server.ts` stands in for the Odin binary. Serving bundles from `#load` with negotiation, and the race against
  Odin's own stream routes, are **UNVERIFIED (M1 for serving, M2 for `bundle-race.spec` on the binary)**.
- Firefox: **UNVERIFIED (CI `e2e`)**. Real Safari: not run.
- brotli on Linux came from an extracted `.deb`. The CI runner images and Debian ship it (11 §9.1), but the CI job
  and the Dockerfile must install or find it: **UNVERIFIED (M1 CI)**. macOS: **UNVERIFIED**.
- Git for Windows' `brotli.exe` was present in the full installer on this PC, and its file list
  (`git-for-windows/build-extra` `make-file-list.sh`) does not exclude it. MinGit and portable installs:
  **UNVERIFIED**; the tool warns and ships gzip and identity.
- `odin build` compiles `_test.odin` files, so a package only a test imports is in the list. If it declares `EXTS`,
  boot check 6 refuses the binary. Rule for M1: a test imports no package that declares `EXTS` beyond what `main`
  mounts.
- A repo path with spaces is untested through `cmd /c` on Windows.
- Not built here: the CSS and `_hs` concatenation (§12.1 step 3), the `tools/check exts` lint, and hyperscript's
  upstream `.br` (hyperscript was served as identity). All are M1.
- The box was shared; no timing in this record is a performance claim.
